# 管理后台实施与验收

日期：2026-11-06。范围：`admin-plan.md` 的首版 7 个模块。

## 功能交付

| 页面 | 功能与操作 |
| --- | --- |
| `/admin` | 经营指标、近 7 / 30 天趋势、日期筛选、成交与退款、生成成功率、异常待办 |
| `/admin/users` | 邮箱与 ID 搜索、账户状态与订阅筛选、用户详情、关联业务记录、补偿、封禁与解封 |
| `/admin/billing` | 订单、交易、订阅列表及详情、支付凭证金额、历史权益、月度窗口入口、Creem 管理入口 |
| `/admin/credits` | 积分批次、流水、使用记录、异常预占退回、来源与到期规则 |
| `/admin/requests` | 生成与审核结果、阶段时间线、错误码、耗时、请求与积分结算关联 |
| `/admin/operations` | 配置状态、数据库探测、生成与结账开关、回调尝试、任务历史、异常待办及处理记录 |
| `/admin/audit` | 操作者、原因、变更摘要、成功与失败记录、关联操作 ID |

所有列表提供分页；搜索、状态与日期条件适用于业务列表。金额查询保留测试与生产环境过滤。详情链接串联用户、订单、交易、积分批次、生成请求与使用预占。

## 数据与服务

- 迁移 `005_admin.sql` 增加用户档案、补偿类型、请求追踪、交易金额、退款增量、回调尝试、操作审计、运营开关、任务与异常处理记录。
- Google 登录写入用户档案；旧会话在后续登录时补齐邮箱和姓名。历史账户通过订单与积分 owner 回填，并标记为历史资料。
- 补偿、封禁、恢复和运营开关使用事务与操作 UUID；重复请求不重复变更权益，冲突操作 ID 被拒绝。
- 补偿生效时间采用数据库时钟；审计与业务变更共享事务。欢迎、购买、订阅和补偿来源进入账户展示及消费逻辑。
- 生成错误携带请求编号；元数据包含阶段、语言、模型和结算关联，不包含图片、描述正文或供应商响应正文。
- Webhook 写入金额凭证和正向退款增量，保持事件去重与支付核验；具有订单证据的尝试记录关联本地订单。
- 恢复任务保留运行记录；鉴权入口 `/api/cron/operations` 提供预占恢复与元数据清理。
- 迁移器记录文件哈希与执行状态，重复运行跳过历史迁移。开发数据库迁移与重复执行验证通过。

## 启用方式

1. 在部署环境填写 `ADMIN_USER_IDS=google:你的GoogleSubject`。多个 ID 使用逗号分隔；邮箱不属于权限标识。
2. 执行 `pnpm db:migrate`，使用 Google 登录后访问 `/admin`。
3. 配置 `AUTH_URL` 为网站来源地址，保持登录、同源校验与实际访问域名一致。
4. 配置私有 `CRON_SECRET`，由部署调度器每五分钟请求 `/api/cron/operations`，携带 Bearer 鉴权。`USAGE_RECOVERY_INTERVAL_MINUTES=5` 用于后台显示预期间隔。

替代调度方式：每五分钟运行 `pnpm usage:recover`，每天运行 `pnpm operations:prune`。调度入口和命令包含实现；平台调度配置由部署环境完成。

详细配置与业务规则见 `SETUP.md` 的 Administration 部分。

## 界面方向与复核

方向为 **Framed Sheet**，seed **1671118711**。沿用 Libre Franklin 字体与品牌蓝色；蓝灰色外框、白色工作区、业务状态与数据使用颜色。外框承担导航，工作区承担查询和处理；签名元素为请求、积分、交易之间的编号追踪链路。

| 页面 | 页面回答的问题 | 1440 / 768 / 390 布局检查 |
| --- | --- | --- |
| 概览 | 哪些业务需要处理？ | 0 FAIL、0 WARN |
| 用户 | 账户的权益从何而来？ | 0 FAIL；桌面短列表留白警告 |
| 订单与订阅 | 交易与权益是否匹配？ | 0 FAIL；桌面短列表留白警告 |
| 积分 | 每笔积分因何变化？ | 0 FAIL；桌面短列表留白警告 |
| 生成与审核 | 请求在哪个阶段结束或失败？ | 0 FAIL；桌面短列表留白警告 |
| 系统与任务 | 服务与恢复任务是否具备运行条件？ | 0 FAIL、0 WARN |
| 操作日志 | 谁在何时执行过何种变更？ | 0 FAIL；桌面短列表留白警告 |

保留的留白警告来自验收数据量小、工作区保持视口高度；列表按记录数呈现，不添加占位业务行。日期、状态、表单与数字在手机布局中重排为字段列表；金额和积分使用等宽数字并右对齐。宽屏、平板与手机的截图用于复核导航折叠、边界、列表、趋势、空态与操作反馈。

人工复核结论：页面标题与主要任务对应；指标和趋势读取同一业务来源；零值与未采集数据区分；金额与积分提供关联详情；手机页面无横向溢出。平板密集表格采用截断与详情入口，详情保留字段全文。界面使用业务数据与图标，无外部摄影、生成图片或虚构增长数字。

## 外部验收与后续范围

部署环境需要配置管理员名单、调度鉴权与调度计划。Google OAuth、Gemini、SeeAPI 和 Creem 的真实服务流程使用对应部署凭证验收；本次数据库测试与浏览器验收未产生供应商付费调用。

退款、取消订阅及事件重发通过 Creem 管理端处理，本后台读取同步结果。客服与财务角色、后台退款、渠道归因、模型成本、优惠活动、邮件、工单与导出保持后续版本范围。
